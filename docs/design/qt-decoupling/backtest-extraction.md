# 回测引擎「摘出来」决策草案（ADR-D11）

> 状态：**提议，待确认** ｜ 提出：2026-10-19
> 用户诉求：「我想把回测摘出来，最多是让回测引擎支持实盘」
> 配套：[backtest-engine-review.md](backtest-engine-review.md)（BE-01~BE-16 问题本）· [target-module-topology.md](target-module-topology.md)

## 结论

**方向认同**（与 ADR-027 的"回测服务"一致），但有两处必须修正，否则摘出来的是一团而不是一个模块。

---

## 修正 1：依赖方向必须反转（这是最关键的发现）

**现状实测**：`pkg/live` **不** import `pkg/backtest`（零命中）；反过来 `pkg/backtest` 持有实盘通道。

证据 `pkg/backtest/execution/live_bridge.go`（文件头注释原文）：
> 「LiveBridge — 引擎与 live.LiveTrader 之间的桥接组件……持有一个可选的 live.LiveTrader（paper / 真实券商），通过 ExecuteSignal / ExecuteSignals 转发策略信号到 broker……该文件从 `pkg/backtest/engine.go`(1408 行 God Object) 中抽离」

即：**依赖方向是 `回测 → 实盘`**，引擎里长着一条实盘通道。

而"让回测引擎支持实盘"在架构上要求的是 **`实盘 → 引擎`**（实盘复用引擎的执行语义）。**两者方向正好相反。**

推论：不先做这次反转，"摘出来"只会把 LiveBridge 一起摘走，边界依旧模糊。

## 修正 2：「支持实盘」的安全边界

| 解读 | 含义 | 判断 |
|---|---|---|
| A | 复用**执行语义**（撮合、成本、T+1、风控裁决规则），驱动层分开 | ✅ 推荐 |
| B | 实盘通道（券商 API、订单生命周期、对账、熔断）也塞进引擎 | ❌ 会让引擎重回 God Object |

**切分判据**：引擎内核 = **纯语义**（给定状态与事件 → 产生订单与成交），**不碰时钟、不碰柜台**。
时钟与历史回放归「回测驱动」；行情流与券商柜台归「实盘驱动」。

## 摘什么 / 不摘什么

| 归属 | 包 | 理由 |
|---|---|---|
| **摘进内核** | `contracts` · `execution` · `tracker` · `metrics` · `auction`（接线后）· `state` | 执行语义与契约（**仅 Go 内核**，不含 nautilus） |
| **同级而非内部** | `nautilus` | 是**双内核中的另一个内核**的适配器，与 Go 内核平级，不是 Go 内核的部件（见下节） |
| **留在内核外** | `job` · `batch` · `walkforward` | 应用编排（BE-03），上移到应用层 |
| **留在内核外** | `reporting` | 分析呈现（BE-13） |
| **必须切断** | `→ pkg/live`（`live_bridge.go`、`engine.go`、`options.go` 三处） | 依赖反转（BE-02） |
| **必须 port 化** | `→ pkg/strategy` | 走 `StrategyRuntime` port（BE-04） |
| **待查** | Engine 内的 `httpClient`（`engine.go:75/330/406`） | 内核不应直连外部（BE-10） |

## 双内核模型（修正：nautilus 不是内核的部件，是另一个内核）

**用户纠正（2026-10-19）**：nautilus 不应放进内核——它是**双内核架构里的另一个内核**。

修正后的模型：

```
               BacktestEngine（port / 能力契约）
                          │
        ┌─────────────────┴─────────────────┐
        ▼                                   ▼
  Go 内核（本仓）                     NT 内核（nt-sidecar · Python）
  进程内 · 逐 bar 循环 · A 股规则     独立进程 · NautilusTrader · HTTP /v1/backtest
  摘出后归「引擎内核」                 有自带的策略注册表（BuyAndHold / WeightReplay）
                                      与自带的撮合引擎
        └─────────────────┬─────────────────┘
                          ▼
        共享：RunSpec / ResultSpec 契约 + 能力声明 + MarketRouter 按能力路由（fail-closed）
        对齐：dualrun K15 双跑对齐 gate
```

**要点**：

1. **共享的是契约，不是实现**。两个内核各自有自己的策略载体、撮合引擎、数据管道。
2. `pkg/backtest/nautilus` 现在是「Go 内核的包里放着一个指向另一个内核的适配器」——这是本次摘出要处理的耦合之一（已登记 BE-17）。
3. 摘出后 `nautilus` 应与 Go 内核**平级**挂在「引擎能力」之下，由注册表按能力选择，而不是住在 `pkg/backtest` 里。
4. 能力与口径一致性**不靠共享代码**，靠三样：能力声明（BE-14）+ fail-closed 路由（已有）+ dualrun K15 双跑对齐（已有）。

## 引擎内核契约（草案，签名待对照现有代码收敛）

```
输入：驱动层提供的「事件流」+ 组合状态 + 风控策略 + 成本参数
输出：订单意图 → 裁决结果 → 成交记录 → 组合变动 → 绩效数据

内核不持有：时钟、行情源、券商连接、任务队列、报表格式
内核保证：同输入同输出（确定性），防前视由契约级把关
```

## 前置阻塞（不解决就摘不动）

1. **BE-02 依赖反转**：把 LiveBridge 从引擎移出，改为实盘驱动持有引擎。
2. **BE-03 编排上移**：job / batch / walkforward 移出 `pkg/backtest`。
3. **BE-04 策略走 port**：否则摘出去还得拖着 `pkg/strategy`。
4. **BE-14 能力声明**：引擎声明能力（频率/市场/模式=backtest|live），路由按能力选引擎。

## 非功能冲突（必须正视）

| 维度 | 回测要求 | 实盘要求 | 冲突点 |
|---|---|---|---|
| 执行 | 严格串行、可重放 | 异步、低延迟 | 同一套循环难以同时满足 |
| 状态 | 可断点、可重置 | 不可回退、需持久化 | 状态管理策略不同 |
| 正确性 | 确定性 > 真实性 | 真实性 > 确定性 | 撮合细节取舍不同 |
| 失败 | 报错即停 | 需熔断、对账、补单 | 故障模型完全不同 |

**结论**：共享**语义**，不共享**运行时**。这也是"最多支持实盘"这句话的安全落点。

---

## 分期（建议）

- **E1 · 断依赖**：移除 `backtest → live`（LiveBridge 迁到实盘侧）+ 移除 Engine 内 httpClient（若用途非内核）
- **E2 · 清内核**：job / batch / walkforward / reporting 移出；strategy 走 port
- **E3 · 立契约**：内核接口 + 双驱动（BacktestDriver / LiveDriver）+ 能力声明
- **E4 · 可选独立部署**：满足条件后才把引擎做成独立进程（触发条件同 ADR-D9：多机部署 / 算力打满 / 团队分组）
