# QT-02 · 两口径成交差异报告（same_close vs next_open）

> 本报告由 `//go:build qt02report` 的生成器产出，数据/参数见「复现」。**它是 docs/SPEC.md「成交时点与已知偏差」与 DefaultFillTiming 切换纪律的依据。**

## 结论

- **机制差 = 成交日与成交基准价，两口径各自落在自己那一端**：same_close 的 15474 笔市单成交里 **88.0%** 的成交价 = 成交日那根 bar 的**收盘** ×(1±滑点)，next_open 的 11048 笔里 **83.2%** = **开盘** ×(1±滑点)；交叉污染几乎为零（same_close 落在开盘端 0.01%，next_open 落在收盘端 0.39% —— 那批是当日开盘价=收盘价的角落，单列在「开=收」）。
- **「T 收盘决策 → T+1 开盘成交」这条时序在真数据上成立**：next_open 落在开盘端的 9194 笔里，**100.0%** 的**前一交易日**该标的确有信号；对照 same_close 落在收盘端的 13615 笔，当日有信号的占 **99.9%**。日期问题是**先按价格分好类再问**的 —— 无条件地问「成交当日/前一日有没有信号」会被信号密度淹掉（momentum 这类每天对多数标的出声的策略，两种问法同时高命中，判据失去分辨力；这段弯路和它的数写在 `classifyFills` 的注释里）。
- **有一类成交本来就不该落在开盘或收盘上：限价单**。本次 same_close 的 393 笔、next_open 的 365 笔价格等于该标的在成交日或前一交易日发出的 limit 价（`bollinger_mr` 按布林带上下沿发限价单），另有 4.5% / 8.0% 落在当日 [low, high] 之内但对不上任何基准 —— 其中 172 / 187 笔的成交日 close 正好贴在 high 或 low 上（涨跌停日引擎把基准价换成整分位限价，见「切换影响」第二条），剩下的 **590 / 776 笔本报告没有归因**（「流动性上限跨日顺延」这条假设实测为 0，已删；不当有解释）。**QT-02 只管市单的成交基准**：限价单换口径时**成交日照样后移**，但成交价仍由策略指定 —— 这条边界写在 docs/SPEC.md「成交时点与已知偏差」。
- **台账 §8.1 那句「差异 ≈ 日收益平移一个 bar」只能在成交层读，在收益层是假的**（表「平移一格检验」）：把 next_open 的日收益序列整体往后挪一格**不会**让它更贴近 same_close。口径差不是一条被延迟的净值曲线 —— 仓位早一天/晚一天变动，改变的是成交那两天的曲线形状（隔夜跳空 + 日内各一段），不是整条曲线的位移。逐笔的 T 收盘 → T+1 开盘由 `pkg/backtest/qt02_fill_timing_test.go` 用合成 bar 断言到具体价格；本表的存在是为了拦住后来人拿日收益相关性当证据。
- **实际差距的量级看「测量」表**：本次 24 只 × 2024-01-02..2025-12-31。总收益差最大的是 `td_sequential`（same_close -55.33% vs next_open -38.90%，差 16.4 个百分点，两年换手 = 本金的 566 倍）—— 每次换仓都把一次隔夜跳空吃进成本，所以口径对高频换仓的策略最敏感；差最小的是 `bollinger_mr`，只有 0.43 个百分点。**这不是「哪个口径对」的裁决**：§8.1 的立场是 next_open 更接近可执行现实，same_close 带着 `known_bias: same_close_fill` 继续可用，**不允许**为了保住某个历史基准数字而选口径（QT-02 ④）。
- **「同环境重跑 ±0」的覆盖面是有条件的**：无重复信号的策略（本次 momentum 等）逐位一致，这条是被执行过的断言；有「同日同标的重复信号」的策略同参复跑实测**会漂**（笔数与总收益都变），表「同参重跑的稳定性」给了数。所以对后一批策略，本报告的数值是**一次抽样**而不是可复现基准 —— 这是 QT-04 要裁的债，不由本单修（见该表下的说明）。
- **切换默认值的代价如实登记在「切换影响」**：末日信号没有成交日、K15 的 NT 腿只实现收盘成交、止损/止盈/末强平仍按收盘（本单只管信号驱动的建仓时点）。

## 同参重跑的稳定性（⑤ 那条 ±0 的真实覆盖面）

验收要求「切换后基准结果与报告数值一致（同环境重跑 ±0）」。这句只在**无同日同标的重复信号**的策略上成立 —— 上面 ±0 断言跑的是 momentum（重复天数 0），逐位一致是被执行过的断言，不是承诺。下面这些策略有重复信号，同参复跑被实测了两次：

| 策略 | 同日同标的重复天数 | 首跑笔数 | 复跑笔数 | 首跑总收益 | 复跑总收益 | 逐位一致 |
|---|---|---|---|---|---|---|
| td_sequential | 468 | 13281 | 13067 | -0.5533 | -0.7250 | 否 |

**这就是 QT-04 要裁的东西的实测代价**：同一份参数、同一个库、同一次进程，笔数和总收益在两次跑之间就变了（差异来自重复信号走进 `map[symbol]` 覆盖，最后一条生效取决于未排序的遍历顺序 —— 见 QT-04 的 ②上下文与 `p0-round2-review.md` §8.3）。对这批策略，本报告的任何数值都是**一次抽样**，不是可复现基准；两口径的**差**因此也只在这一次抽样内可比。结论第 5 条引的最大差距数同样受此影响。

## 切换影响（如实登记）

- **区间最后一天的决策没有成交日**：next_open 下这部分信号不成交（表「测量」最后一列），引擎把它计进 run 级诊断 `next_open_unfilled_at_run_end`，不退回收盘价补上。
- **T+1 停牌或开盘价不可用 = 拒单，不顺延回收盘**：计入 `next_open_no_fill_price`。理由写在 `pkg/backtest/engine_daily.go` 的 `openPricesForSignals`：一条 provenance 记录里混两种成交基准，比少一笔成交更糟。
- **成交基准价就是引擎选定的价**：`executeViaExecutionService` 原先用 `DayBar.Close` 覆盖它，本单修掉了（否则 next_open 是假实现 —— 「成交层证据」表里 next_open 那一行会全部落到「=当日收盘」，而请求里写着 next_open）。这正是 §8.1 要求「回报里带口径而不是靠请求推定」的原因。
- **NT 腿仍只实现收盘成交**：侧车对 next_open 直接拒收（400），K15 的 Go 腿则显式钉 `same_close`，所以默认值切换不会悄悄改变双跑口径 —— 见 `cmd/dualrun/gate.go:CheckCaliberParity`。
- **止损/止盈平仓、退市强平、区间末强平仍按当日收盘可成交价**：本单只管信号驱动的建仓时点（边界写在 SPEC）。所以「开盘批·前一日有信号」的分母里不含这些成交，两口径的这部分完全同形。
- **qfq 复权基准快照接内存**：本机的 `backtest_adjustment_anchors` 里 2026-10-17 冻结的 `000001.SZ / 2024-01-02` 基准与当前序列已不吻合（库里那段数据后来被动过），REV-18 的漂移守卫 `ErrAdjustmentDrift` 因此拒跑 —— 这是它设计上该做的事（「改价/补行」不能当成「换了个基准」继续算），不是本单缺陷。报告改用内存快照跑当前刻度，**因此本报告的 ±0 只对同一环境成立**；跨月重跑若库被重同步，两列数值会一起移动，差值仍可比。

## 复现

```bash
QT02_PG_DSN='postgres://postgres:postgres@127.0.0.1:5432/quant_trading?sslmode=disable' \
  go test ./pkg/backtest -tags qt02report -run TestQT02FillTimingDifferenceReport -count=1 -v
```

默认参数：票池 24 只（`QT02_UNIVERSE` 可覆盖）｜区间 2024-01-02..2025-12-31｜期初本金 1000000｜滑点 0.001（= 执行服务 fixed 模型）｜佣金 0.0003｜risk_free 0.03（引擎默认）｜seed 42。
可选 `QT02_DEBUG_FILLS=N` 打印前 N 笔成交的原始价与当日 open/close（`QT02_OUT` 改输出路径）。取数：`marketdata.NewPostgresProvider`（直连库，不经 data-service :8081）｜风控：进程内 `risk.RiskManager`（缺它时建仓规模会去打外部 risk-service，静默 0 成交）｜qfq 复权基准快照：内存（见「切换影响」最后一条）。

生成器：`pkg/backtest/qt02_fill_timing_report_test.go`（build tag `qt02report`，库侧入口走 `storage.NewPostgresStoreConnected` —— 连库不迁移）。
